Docker Swarm 支持 · 草图

在现有 Docker 功能上加集群层：服务 / 节点 / 任务 / 栈。复用同一条 dial-stdio 传输—— 连到 manager 时它的 daemon 就是 Swarm 控制面；连到 worker 或非 swarm 主机时不显示集群入口。 版式沿用右栏与详情标签页的既有骨架。
设计要点
① manager 判定：info().swarm 的 control_available==true && local_node_state=="active" 才点亮「服务/节点」两个 segment 与集群徽标；worker 上 /services、/nodes 会 503/406，判定后隐藏入口而非报错刷屏。
② 零新增传输/依赖：bollard 0.21 已带 service/node/task/swarm 全套 API，同一只 DockerClient 直接调。
③ 写操作带 version：扩缩容 / 节点可用性都要先 inspect 拿 version.index 再 update（否则 409），封装内部处理。
④ 栈不单独建模：按 com.docker.stack.namespace label 给服务分组/筛选。
⑤ 一期：服务列表/详情(概览·任务·日志)/扩缩容/删除；节点列表/详情/drain·activate·pause。二期：secrets/configs、overlay 网络、服务创建/改镜像、节点移除（bollard 0.21 未暴露 remove_node）、swarm init/join/leave（破坏性，不做或显式告警）。

只改 replicas。带 version index；global 服务不可扩缩（入口禁用）。

  • b应用后回列表/详情刷新副本列；滚动期间 running/desired 不等属正常（琥珀），任务表能看到新旧 task 交替。

落点（后端 / 分层）

winssh-docker 加 swarm 模块：类型（ServiceSummary/ServiceDetail/TaskSummary/NodeSummary/SwarmInfo）+ client 方法 （swarm_info、list_services、inspect_service、service_logs、scale_service、remove_service、list_tasks、list_nodes、inspect_node、set_node_availability）。 scale/availability 内部先 inspect 取 version 再 update。
DockerService 加对应入口（长流 service_logs 走现有 channel 模式）。
UI：DockerView 按 swarm_info 判定加「服务/节点」segment 与集群徽标； 新增 DockerServicePanel / DockerNodePanel 两个 dock 标签页（照 DockerContainerPanel：带 host_tab、概览/任务/日志分段、复用确认弹窗与日志组件）。 服务/节点列表行复用容器行的定高+悬停动作版式。
不做：remove_node（上游未暴露）、swarm init/join/leave、secrets/configs/overlay（二期）。
