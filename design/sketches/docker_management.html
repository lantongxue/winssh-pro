Docker 容器管理 · 草图

入口在右活动栏（监控之后第 5 枚），跟着中心区活动的那条 SSH 会话走 —— 管的是那台主机上的 Docker。 版式沿用右栏现有骨架：36px 标题行、380px 默认宽、列表 + 居中弹窗（与转发页同款分工）。
设计要点
① 不另开连接：在现有 russh 会话上开一条 exec 通道跑 docker system dial-stdio，字节流接进 bollard（Docker Engine API 客户端）—— docker CLI 的 ssh:// 上下文同款机制，权限就是该用户的 docker 权限，rootless 自动跟随。
② 容器终端不做内嵌：点「终端」新开一个同主机终端标签页跑 docker exec -it … sh，整条终端栈（分屏/滚动/zmodem）白捡。
③ 列表便宜、详情才贵：列表可见时 3s 轮询 + 手动刷新，不给每行拉 stats（N+1）；CPU/内存/网络只在详情弹窗开着时拉一条流。
④ 危险操作二次确认：删除容器/镜像、停止运行中容器都弹确认；删运行中容器要显式勾「强制」。
⑤ 一期范围：容器列表 / 起停重启删 / 日志 / 终端 / 容器文件管理（浏览·上传·下载·新建目录·重命名·删除）/ 镜像列表 / 拉取 / 删除。二期候选：运行容器表单、文件在线编辑、docker events 推送刷新、网络与卷、Compose、端口一键联动转发。
⑥ 文件管理两条路：上传/下载走 Engine API 的 archive（tar 流，停止的容器也能用，不依赖容器内二进制）；列举/改名/删除走 exec（运行中且有 shell），没 shell 的镜像列举退回 archive 读 tar 头。

  • a列举两条路：运行中 → bollard exec 跑一层 POSIX 列举脚本（类型/大小/mtime/权限/软链目标，monitor 同款做法）；没 shell（distroless/scratch）或已停止 → archive API 拉 tar 只读条目头。面包屑 + 上级，与 SFTP 面板同款导航。

落点与选型（后端，不在画面里）

库：bollard 0.21（Rust 事实标准的异步 Docker Engine API 客户端，Apache-2.0，活跃维护）。 default-features = false, features = ["http", "chrono"] —— 不带 TLS、不带 openssh、不带 buildkit； hyper / hyper-util / tokio / serde / serde_urlencoded / serde_repr 全在现有依赖树里（逐个对过 Cargo.lock），新增编译只有 bollard + bollard-stubs 两个 crate。
不用它自带的 ssh 特性：那会经 openssh crate 拉起系统 ssh 二进制重新认证，绕开我们已经建好的 russh 会话（密码 / 跳板 / 代理 / 2FA 全丢）。
接线：现有 russh 会话 → 新 exec 通道跑 docker system dial-stdio → channel.into_stream()（sftp/转发已在用）→ 包成 hyper 流 → Docker::connect_with_custom_transport。bollard 自己的 ssh.rs 就是这个形状，照抄结构、换掉传输。
分层：新后端 crate winssh-docker（连接器 + 客户端 + 领域类型）→ winssh-service 加 DockerService → UI 加 SessionTool::Docker / DockerView（常驻终端标签页，bind / set_visible 与转发页同款）+ 详情弹窗。备选传输 direct-streamlocal 转发 docker.sock（russh 0.65 已支持），留作二期开关。
文件管理：bollard 的 archive 三件套（get_container_archive_info HEAD stat / download_from_container GET tar / upload_to_container PUT tar）+ exec 列举 —— 停止的容器也能浏览与传输；版式、本地落盘与编辑器复用 SFTP 面板基建。
